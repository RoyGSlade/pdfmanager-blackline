# PDFManager

PDFManager is a shareable, browser-based PDF workbench from Underplain. It does
one job well: open a local PDF, make reversible edits, and export a verified new
copy without sending the document to an application server. It can also recover
printed tables as editable spreadsheets.

This is the MVP, not an Acrobat clone. The browser workflow is real and tested;
desktop packaging, redaction, certificate signing, and broad PDF
interoperability are deliberately outside this release.

## MVP scope

- Open a PDF from the file picker or drag and drop (up to 100 MB).
- Render pages locally, navigate thumbnails, zoom, and search extracted text.
- Inspect page dimensions, form fields, file size, and the source SHA-256.
- Add text, highlights, freehand marks, lines, rectangles, checkmarks, PNG/JPEG
  stamps, and electronic signature appearances.
- Fill supported AcroForm text, checkbox, dropdown, and radio fields.
- Undo/redo; reorder, rotate, duplicate, delete, and insert pages.
- Use **Table** to recover rows from scanned or selectable-text PDFs, adjust
  columns, edit headers and cells, and download CSV or Excel.
- Export one flattened PDF copy, reopen it in memory, validate its structure and
  page count, and confirm the retained source bytes still match their original
  SHA-256 before enabling download.
- Use generated W-9, medical intake, and architecture fixtures without checking
  customer documents into the repository.

## Honest limitations

- Export is flattened. Standard editable annotation interchange is not claimed.
- Encrypted PDFs, XFA, PDF JavaScript, existing certificate signatures,
  secure redaction, and complex form structures are not qualified.
- Table recovery uses English OCR on scan-only pages and is designed for upright
  printed tables. Check flagged cells and account IDs against the scan. Use Excel
  when leading zeros matter since spreadsheet apps can reinterpret CSV values.
- The proof pass validates the generated bytes in memory. It does not prove how
  every third-party PDF reader will render the file or reopen the downloaded
  file from disk.
- Saved signatures are an explicit opt-in convenience stored unencrypted in the
  browser profile. Do not save sensitive signatures on a shared device.
- The app code has no document-upload or telemetry endpoint, and the PDF.js
  worker and fonts are bundled locally. Browser extensions, the hosting layer,
  and the user's device remain outside the app's trust boundary.
- Browser memory and canvas limits still apply. This is not a signed desktop
  application.

## Run locally

Requires Node.js 22.13 or newer.

```bash
npm ci
npm run dev
```

Open `http://localhost:3000`, choose **Try Sample PDF**, or open your own file.
No API key or backend service is required.

## Offline on Windows

Use **Start PDFManager.cmd** from the installed local PDFManager folder. It
serves the bundled app on loopback. Keep that copy available for work documents:
some organizations restrict opening internal files on public domains even when
the browser handles the files locally. Follow your organization's policy.

## Deploy to donavencrenshaw.com

```bash
npm ci
npm run build:domain
npx wrangler deploy --dry-run
```

The domain build writes `dist-domain/` with Vite's
`/pdfmanager/` base. Its canonical and social links target
[donavencrenshaw.com/pdfmanager/](https://donavencrenshaw.com/pdfmanager/).
The default `npm run build` still produces a root build for offline
use. The GitHub Pages build can still set its own asset base.

The live apex serves the rest of the website from GitHub Pages. The supplied
Wrangler config is for a Cloudflare Worker route on the existing apex. Before
activation, verify that the apex record is proxied in Cloudflare, the GitHub Pages
origin is healthy through the proxy, and TLS is set to **Full (strict)**.
The route covers the workbench and forwards any other prefix match to the
existing origin. Keep the Worker first so the security headers apply to both
HTML and assets. Once ready, run `npx wrangler deploy` from an account
with access to the zone.

Verify that HTTP redirects to HTTPS, and that HTTPS returns the expected
canonical URL, Content-Security-Policy, X-Content-Type-Options and
Referrer-Policy headers. Open the sample, render its pages, and export a copy
in a fresh browser session. Also check the homepage and
`/underplain/pdfmanager/` through the proxy. Remove the Worker route to
roll back just the workbench.

## Quality gates

```bash
npm run check
npm run test:e2e
```

| Command | Purpose |
| --- | --- |
| `npm run typecheck` | TypeScript no-emit check. |
| `npm run test:unit` | Vitest engine and utility tests. |
| `npm run test:e2e` | Playwright Chromium user-journey tests. |
| `npm run build` | Production Vite build. |
| `npm run check` | Typecheck, unit tests, and production build. |

The browser harness may need `npx playwright install chromium` once on a new
machine. GitHub Actions runs install, typecheck, unit tests, browser tests, and
the production build on every push to `main` and every pull request.

With standalone GitHub Pages enabled, pushes to `main` also build the app with the `/pdfmanager-blackline/` base path
and deploy `dist/` through the included GitHub Pages workflow.

## Contribution rule

Keep UI components behind typed context/engine contracts. Every PDF behavior
needs a generated fixture or deterministic test, and every unsupported format
needs honest user-facing copy. Run `npm run check` and `npm run test:e2e` before
opening a pull request.
